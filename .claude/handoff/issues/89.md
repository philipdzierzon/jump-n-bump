# #89 Connect and Rejoin have no in-flight state, and can silently do nothing

**state:** open  **labels:** bug, ready-for-agent

> *This was generated by AI during triage.*

## Parent

#81 §6.6 and §6.3 — cut out of the loop/relay/flow audit.

## What to build

Two controls that can silently do nothing, and give the player no way to tell.

**A — Create, Password and Quick Join have no in-flight state, and repeat clicks open extra sockets.** The connect path has no pending guard and the submit buttons carry no enable binding. Nothing visibly changes on the first click, so the player clicks again — and the orphaned socket is pinged and ponged regardless of whether it is still the active transport, so **an orphan room appears in the public list with a host that will never leave**.

**B — "Rejoin the match" latches and never recovers.** The resuming flag is set when the rejoin starts and cleared on only three paths. The session builder returns early in one case, and the level fetch's rejection is a no-op, so a failure on either leaves the flag set: "Rejoin the match" visibly does nothing, silently, for the rest of the match. No timeout, no message.

## Acceptance criteria

- [ ] Create, Password and Quick Join are disabled while a connection attempt is in flight, and repeat clicks cannot open a second socket
- [ ] A superseded socket is closed rather than left answering pings, and no orphan room reaches the public list
- [ ] A failed rejoin clears its in-flight state and tells the player it failed
- [ ] A rejoin that neither succeeds nor fails within a bounded time is treated as a failure
- [ ] A failed level fetch during a rejoin surfaces rather than being swallowed
- [ ] A browser test double-clicks Create and asserts one room is created
