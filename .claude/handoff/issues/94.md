# #94 The client's JSON.parse is unguarded, so one malformed frame kills the page

**state:** open  **labels:** bug, ready-for-agent

#81 §7 — cut out of the loop/relay/flow audit.

## What to build

The client's WebSocket transport parses every incoming frame with no try/catch, while the relay's own parse is guarded. One malformed frame therefore kills the page's message handling mid-match: the socket stays open, the player sees a live-looking page, and nothing arrives ever again.

The asymmetry is the whole bug — the relay already decided this is a real case and handled it.

## Acceptance criteria

- [ ] A malformed frame is discarded and the page keeps handling subsequent messages
- [ ] A discarded frame is visible to a developer rather than silently swallowed
- [ ] A test sends a malformed frame mid-match and asserts the next valid message is still handled
- [ ] The transport's stale comment listing reserved seats, AI takeover and reconnect as future work is deleted — all three shipped in #42

## Out of scope

- Validating the *contents* of well-formed messages on the client
- The relay's own parse, which is already guarded
