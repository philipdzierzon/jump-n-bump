# #82 The relay accepts four message types from any client without checking who sent them

## What to build

The relay's message switch checks `client.host` on `begin`, `cancel` and `config`, and validates the seat on `claim_seat` and on `input`. Four other message types are accepted from any connected client with no ownership check and no validation at all. Close all four on the same switch, plus two sibling input-trust holes in the same file.

**2.1 — an unbounded `t` hangs the whole Node process.** The `input` case bounds `msg.t` below but not above, then raises the room's tick to `msg.t + 1`. Substitution then loops from the room's due tick to that new tick with no bound, doing a linear scan of the stamped array per seat per tick and broadcasting a frame per iteration. One `{"type":"input","t":1e9}` spins the single process for the rest of the day — **every room on the relay freezes, not just the sender's**. The client half of this shipped in #80; this is the other half. Note the client drops the absurd frame on receipt, so the symptom is room-side tick poisoning, not a visible desync.

**2.2 — `driver` is unauthenticated and unvalidated.** No host check, no check that the client holds the seat, no range check on the seat, no allowlist on the driver value. Any peer hands another player's bunny to the AI mid-match. `driver: "local"` for a seat you do not hold also clears that seat's missing-tick counter, permanently disabling AI takeover for a seat whose holder really has gone. The seat is also unvalidated as an index, so the driver map can be written at an arbitrary property. The `input` case already enforces seat ownership and counts a violation as forged — this case should be consistent with it.

**2.3 — `match_end` is unauthenticated.** It ends the match and rebroadcasts the final board verbatim. Any peer ends everyone's match and dictates the result. The comment above it says "exactly as the host sent it", so host-only is the intent; the check is simply absent. The client-side board-shape guard bounds the *shape* of a forged board, not the right to send one.

**2.4 — a malformed `pong` sets the room's input delay to `NaN` for the whole match.** The one-way time is computed from `msg.at` with no finite guard, and the delay clamp is `Math.min(10, Math.max(2, …))`, which does **not** defeat `NaN`. Substitution's comparison then never holds — no substitution at all for the entire match — and the delay serialises over JSON as `null`, so every client stamps with zero delay. The delay is derived once at match start and fixed, so the room is unplayable until it is remade.

**Two more input-trust holes in the same file, folded in because they are the same PR:** the `create` handler passes the password through without coercing it while the host-config handler coerces with `String(...)`, and the two are compared with `!==` — a non-string password makes the room permanently unjoinable, the host included. And the switch has no `default`, so an unknown message type is dropped in silence.

## Where it lives today

`server/index.js`, the `relay()` switch and the `create` handler. The catch-up ceiling and the list of valid driver values exist only on the client (`src/net/room.js`); the relay has neither. `server/index.js` already imports `src/net/room_config.js`, so that is a working home for both as shared constants.

## Acceptance criteria

- [ ] An `input` whose tick is further ahead of the room's tick than the catch-up ceiling is rejected, and the room's tick is not advanced by it
- [ ] A `driver` message is rejected unless the sender holds that seat, the seat is a valid seat index, and the driver value is one of the known drivers
- [ ] A `match_end` from a non-host is rejected and does not end the match or broadcast a board
- [ ] A `pong` with a non-finite timestamp is ignored, and the room's input delay is always a finite integer inside its clamp
- [ ] The catch-up ceiling and the driver list are defined once and shared by client and relay rather than restated
- [ ] A room created with a non-string password is joinable with that password, or the create is refused — not silently unjoinable
- [ ] An unknown message type is handled explicitly rather than falling off the end of the switch
- [ ] `test/relay.test.mjs` covers each rejection: a forged tick, a forged driver, a non-host match end, a malformed pong
- [ ] The stale comment claiming substitution is "not true yet" is deleted (it shipped in #17)

## Out of scope

- IP-level rate limiting, the reaper and room caps — that is #47, which explicitly accepts "no frame-rate limiting on established sockets" as its ceiling
- Any change to the client's own bound, which shipped in #80
- Server-side simulation or a desync vote — deliberately rejected, see #81 §9
