# #85 Keys stick down on blur, and keep being sent to the room

## What to build

The pressed-keys map is cleared only by a real `keyup`, and the key handlers are bare document-level assignments with no blur or visibility flush. Alt-tab while holding right and the browser never delivers the keyup: the bunny runs right forever — **and keeps sending right to the whole room**, so it is everyone's picture, not a local artifact. The same happens when the `Connection lost` overlay takes focus.

This is also a prerequisite for #51's hidden-tab freeze: freezing a client with a key latched down resumes it mid-sprint.

## Acceptance criteria

- [ ] Losing window focus while a key is held releases that key in the simulation, and the room stops receiving it held
- [ ] The same holds when the page is hidden rather than merely blurred
- [ ] Regaining focus with the key still physically down resumes movement on the next real keydown, not from a latched state
- [ ] The keyboard exposes a way to clear its pressed state rather than callers reaching into it
- [ ] A browser test blurs the page mid-match with a key held and asserts the bunny stops
