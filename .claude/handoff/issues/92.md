# #92 Snapshot and input-ring bookkeeping: a hole on resume, an unbounded array, a discarded tick

**state:** open  **labels:** bug, ready-for-agent

## What to build

Three bookkeeping faults around the relay's snapshot and input history.

**A — the input ring can lose frames a snapshot still needs.** The ring holds a fixed number of frames but is pruned against the snapshot's tick only when a snapshot arrives. A backgrounded host's snapshot interval is throttled by the browser to roughly one a minute, which is more ticks than the ring holds — so the ring has already dropped frames the next snapshot will need, and the resume path ships a snapshot with a hole after it. The joiner replays the hole as released keys and is desynced on landing, **with nothing detecting it**.

**B — the stamped-frame array is unbounded.** It is pruned only when a snapshot is kept. The driver lookup reverse-scans it per seat per tick and the resume path serialises the whole array, so both costs grow without limit over a long match.

**C — an unpacked snapshot's tick is discarded.** It is packed, returned and then dropped by the caller, while the room's tick comes independently from the message. A snapshot that disagrees with the tick it arrived with would be undetectable.

## Acceptance criteria

- [ ] A snapshot is never shipped to a joiner with a gap between it and the frames that follow — either the ring keeps what the snapshot needs, or the resume is refused rather than served with a hole
- [ ] A host whose snapshot interval is throttled does not produce an unserviceable resume
- [ ] The stamped-frame array is bounded over a long match, and the driver lookup does not scan it per seat per tick
- [ ] An unpacked snapshot's tick is compared against the tick it arrived with, and a disagreement is reported rather than ignored
- [ ] `test/relay.test.mjs` covers a resume attempted after a throttled snapshot interval

## Out of scope

- Snapshot contents, which are sound — the packed form carries the tick, the RNG state, every player field and every object slot
- The level travelling as a name, which is its own issue
- Server-side simulation, deliberately rejected
