## What to build

Three holes in the route-applying function, all reached with the browser's own navigation and none covered by a test — the browser suite contains no reload, no Back and no Forward anywhere.

**A — browser Back out of a match is not the same thing as "Back to the lobby".** The button announces the end of the match to the room; routing away from the match screen merely tears down the local session, releasing seats and stopping the simulation while the relay still believes the match is running. A host who presses Back leaves everyone else playing on against AI bunnies in a match that nothing can end.

**B — following a room link while already seated leaves a sixty-second ghost seat.** Leaving the room is announced only when routing to the landing or browse screens; a room-code hash is a join route, so the abandoned room holds the player's empty bunny for the full reservation window, blocking a seat and the countdown for everyone still in it.

**C — the match screen is reachable from the lobby and renders empty chrome.** The match route is accepted whenever a game object exists, and one exists from the lobby onward: the player gets a clock, a "Scores" control and a "Back to the lobby" link over a blank black canvas.

## Acceptance criteria

- [ ] Browser Back out of a live match has the same effect on the room as the "Back to the lobby" control: a host ends the match for everyone, a non-host leaves the match without stranding it
- [ ] Navigating to another room's link while seated releases the seats in the room being left, immediately rather than on reservation expiry
- [ ] The match screen is reachable only when a match is actually running; reaching for it from the lobby lands on the lobby
- [ ] Browser Back, Forward and reload are walked by `test/browser.test.mjs` at each of these three points

- Seat reservation and AI takeover mechanics, which shipped in #42
