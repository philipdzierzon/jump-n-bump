# #88 Five places the flow never says what happened

## What to build

Five places where the machinery works and the page never says what happened. All five are missing text rather than missing behaviour, which is why they are one issue.

**A — the landing screen has no error binding, and three failure paths route there.** Every other screen — create, join, password, names, lobby, browse — carries an error line. The landing screen does not, so a player whose room is gone watches `Reconnecting…` for sixty seconds and then lands on the title screen, never told what happened or why.

**B — countdown-zero ejection is silent.** When the lobby countdown reaches zero the relay vacates the seats and the client routes back to the names screen with no notice. Reading the final board for eleven seconds costs the player their seats, with no sentence anywhere saying so. Ready also resets after *every* match, which is equally unannounced.

**C — a mistyped room code answers with a password prompt.** The first refusal routes to the password screen with no error; the message only appears on the second attempt. The player concludes the room exists and is locked, guesses a password, and only then learns it never existed. Deliberate opacity for unlisted rooms (#8) is a decision about *whether a room is revealed*, not a decision to stay silent on the first attempt.

**D — the lobby never says who the host is.** The player reads "Waiting for the host to start." with no way to tell which of four names that is. The room view sends the host flag only as the recipient's own boolean. The relay already computes `(left)` / `(AI)` / `(out of sync)` labels per seat, and they are used only by the scoreboard.

**E — a failed room-list fetch is indistinguishable from an empty list.** The fetch catches into an empty array, so when the relay is down the page says "Nothing public right now — make one, or join by its code."

## Acceptance criteria

- [ ] The landing screen displays an error, and each of the three paths that route there sets one that names what happened
- [ ] A player whose seats are vacated by the countdown is told so, on the screen they land on
- [ ] Ready resetting after a match is announced rather than silent
- [ ] The first refusal of a room code says the code was not accepted, before any password is asked for — without revealing whether an unlisted room exists
- [ ] The lobby identifies the host among the seated players
- [ ] A failed room-list fetch reads as a failure with a retry, not as an empty list
- [ ] `test/router.test.mjs` covers the wording of each new message, in keeping with how it already covers the line above the board
