# #90 The room flow cannot be driven from the keyboard, and is never announced

**state:** open  **labels:** enhancement, ready-for-agent

> *This was generated by AI during triage.*

## Parent

#81 §6.11 — cut out of the loop/relay/flow audit.

## What to build

The room flow cannot be driven from the keyboard and is not announced to a screen reader. There is no form element anywhere in the markup, no autofocus and no programmatic focus call in any of the interaction code.

- **No Enter-to-submit.** Type a room code, press Enter, nothing happens. Every text entry in the flow has this problem.
- **No focus management.** After every screen change focus falls back to the document body, so a keyboard-only player re-tabs from the top of the page each time.
- **Nothing is announced.** Error messages appear with no live-region role, so a screen reader never hears "That code is taken."

## Acceptance criteria

- [ ] Every text entry in the room flow submits on Enter, to the same action as its button
- [ ] After a screen change focus lands on that screen's first meaningful control rather than on the document body
- [ ] Error and status messages are announced by a screen reader when they appear
- [ ] The whole flow — landing through lobby to a match — is completable with the keyboard alone
- [ ] A browser test walks the flow using only keyboard events

## Out of scope

- Touch input and the names screen's touch path, which belong to #45
- In-game controls during a match
- A full accessibility audit of the match canvas
